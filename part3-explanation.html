סדר פעולות ב-Cypress – Asynchronous Command Queue

Cypress Command Queue
const SearchInputBox = cy.get('.gLFyf');
cy.visit('https://www.google.com/');
SearchInputBox.first().type('Gov.il');

כדי לענות, צריך להבין כיצד Cypress מבצע פקודות בפועל.

מושג מפתח: Cypress Command Queue (תור פקודות)
כל פקודת Cypress כמו cy.get(), cy.visit(), cy.click() לא מתבצעת מיידית. היא מתווספת לתור ביצוע ותרוץ רק כאשר Cypress מוכן — לאחר שהדף נטען, אחרי שהאלמנט קיים.
שורה 1: cy.get('.gLFyf') → מוסיף לתור "חפש אלמנט"
SearchInputBox = Chainer (לא תוצאה אמיתית!)

שורה 2: cy.visit(...) → מוסיף לתור "טען דף"
שורה 3: .first().type(...) → מוסיף לתור "הקלד"

── ביצוע התור ─────────────────────────────
❌ "חפש .gLFyf" ← רץ לפני שהדף נטען! האלמנט לא קיים.
✓ "טען דף"
✓ "הקלד"
גישהדוגמהמה קורה
שמירה במשתנה לפני visit const el = cy.get('.x');
cy.visit(url);
el.click();		 ה-get רץ לפני הדף — האלמנט לא קיים
שרשרת ישירה cy.visit(url);
cy.get('.x').click();		 visit מסתיים לפני get — תקין
התשובה הנכונה היא: Malfunction in the order of operations — תקלה בסדר הפעולות.

הבעיה אינה בסלקטור, בערכים, או בתוכן הפקודות — כולן תקינות לחלוטין. הבעיה היא ש-cy.get('.gLFyf') נרשם בתור הפקודות לפני cy.visit(). כאשר Cypress מריץ את התור, הוא מנסה למצוא את האלמנט על דף שעוד לא נטען — ולכן הטסט נכשל. הפתרון: תמיד לשים cy.visit() לפני cy.get().

driver.getPageSource() – הסבר מלא ומפורט למתחילים

Selenium WebDriver HTML & DOM Server vs Browser
🔧 רקע: מה זה Selenium WebDriver?

Selenium הוא כלי בדיקות אוטומציה לאינטרנט. הוא מאפשר לקוד שלנו "לנהוג" בדפדפן — לפתוח דפים, ללחוץ על כפתורים, למלא טפסים — בדיוק כמו שמשתמש אמיתי.

driver הוא האובייקט המרכזי — הוא מייצג את הדפדפן שנפתח. דרכו שולחים פקודות: "לך לדף", "מצא אלמנט", "לחץ", "קרא טקסט".

דימוי: Selenium = נהג מונית אוטומטי.
driver = שלט הרחוק שמפקד על המונית.
כל פקודה שכותבים ב-driver היא הוראה שהדפדפן מבצע בפועל.

ההבדל בין Selenium ל-Cypress:
Cypress רץ בתוך הדפדפן ולא צריך driver. Selenium רץ מחוץ לדפדפן ומתקשר איתו דרך פרוטוקול WebDriver.

📄 מושג בסיס: מה זה HTML ומה זה DOM?

HTML (HyperText Markup Language) הוא שפת הסימון שמגדירה את מבנה דף האינטרנט. זהו קובץ טקסט פשוט עם תגיות (tags) כמו <div>, <p>, <button>. 

<!-- דוגמה לקוד HTML -->
<html>
  <head>
    <title>gov.il</title>
  </head>
  <body>
    <h1>ברוכים הבאים</h1>
    <button id="search-btn">חיפוש</button>
  </body>
</html>

DOM (Document Object Model) הוא הייצוג בזיכרון הדפדפן של אותו HTML. כשהדפדפן קורא את ה-HTML, הוא בונה ממנו מבנה עצים (tree) בזיכרון — זה ה-DOM. JavaScript יכול לשנות את ה-DOM לאחר הטעינה — מבלי לגעת בקובץ ה-HTML המקורי.

דימוי:
HTML = תוכנית הבנייה של בית (על נייר).
DOM = הבית עצמו לאחר הבנייה בזיכרון.
JavaScript יכול לשפץ את הבית (DOM) מבלי לשנות את התוכנית המקורית (HTML).
חשוב: ה-DOM יכול להיות שונה מאוד מה-HTML המקורי! JavaScript מוסיף, מסיר ומשנה אלמנטים ב-DOM לאחר שהדף נטען.
⚡ מושג בסיס: מה זה JavaScript ואיך הוא משנה את הדף?

JavaScript (JS) היא שפת תכנות שרצה בתוך הדפדפן. היא מאפשרת לדפים להיות דינמיים — לשנות תוכן, לשלוח בקשות לשרת, להציג ולהסתיר אלמנטים. 

// JavaScript שמוסיף אלמנט חדש ל-DOM
const newDiv = document.createElement('div');
newDiv.textContent = 'תוכן שנוצר ב-JavaScript';
document.body.appendChild(newDiv);

// האלמנט קיים ב-DOM — אבל לא בקובץ ה-HTML המקורי!

אתרים מודרניים כמו React, Angular, Vue שולחים HTML כמעט ריק מהשרת, וה-JavaScript בונה את כל הממשק בדפדפן.

מה השרת שולח (HTML גולמי)
  • HTML בסיסי, כמעט ריק
  • קישורים לקבצי JavaScript
  • אין תוכן ויזואלי עדיין
מה המשתמש רואה (DOM אחרי JS)
  • כפתורים, תמונות, טקסטים
  • כל הממשק — נבנה ע"י JS
  • שונה לחלוטין מה-HTML שהגיע
🔍 מה עושה driver.getPageSource() בדיוק?

driver.getPageSource() מחזירה מחרוזת טקסט (String) שמכילה את קוד ה-HTML של הדף — כפי שהדפדפן רואה אותו ברגע הקריאה. 

// Selenium – Java
String source = driver.getPageSource();
System.out.println(source);

// הפלט: <html><head>...</head><body>...</body></html>
נקודה עדינה: האם getPageSource מחזיר את ה-HTML שהגיע מהשרת או את ה-DOM אחרי JS?

התשובה תלויה בדפדפן — בדרך כלל מחזיר את ה-HTML כפי שהוא בדפדפן ברגע הקריאה, אחרי שה-JS רץ חלקית. הוא שונה מ-driver.findElement() שמחפש ב-DOM החי.
שרת ──── שולח HTML ────► דפדפן
(קוד מקור) (מפרש)

דפדפן ──── JS רץ ─────► DOM מעודכן
(JavaScript) (ממשק ויזואלי)

getPageSource() ◄── HTML + שינויים חלקיים
findElement() ◄── DOM החי — מה שמוצג למשתמש
🗂 מה יש ב-Page Source שאי אפשר למצוא ב-DOM?

ישנם מקרים שהמידע נמצא ב-HTML אבל לא גלוי כאלמנט ב-DOM:

1. תגיות <script> עם JSON מוטמע

<!-- מידע שהשרת מכניס ישירות ל-HTML -->
<script type="application/json" id="initial-data">
  {
    "user": { "id": 123, "role": "admin" },
    "config": { "lang": "he", "version": "2.1" }
  }
</script>
<!-- לא גלוי למשתמש, לא אלמנט ב-DOM — רק getPageSource() יחשוף אותו -->
מה זה JSON?
JSON (JavaScript Object Notation) הוא פורמט להעברת נתונים בין שרת לדפדפן. נראה כמו מילון: {"key": "value"}. השרת משתמש בו להעביר מידע מובנה (כמו פרטי משתמש, הגדרות, נתוני API).

2. Meta Tags — מידע על הדף

<head>
  <!-- תגיות meta לא גלויות למשתמש -->
  <meta charset="UTF-8">
  <meta name="description" content="ממשלת ישראל">
  <meta property="og:title" content="gov.il">
  <meta name="csrf-token" content="a8f3k...">
</head>
מה זה Meta Tag?
תגית <meta> מכילה מידע על הדף, לא מידע שגלוי בדף. הדפדפן משתמש בה לצרכי:
  • charset — קידוד תווים (חשוב לעברית)
  • description — תיאור לגוגל (SEO)
  • og:title — כותרת לשיתוף ברשתות חברתיות (Open Graph)
  • csrf-token — טוקן אבטחה נגד התקפות CSRF
המשתמש לא רואה אותן בדף — רק בקוד המקור.

🌐 Server-Side Rendering vs Client-Side Rendering
Server-Side Rendering (SSR) Client-Side Rendering (CSR)
איך זה עובד השרת בונה HTML מלא ושולח לדפדפן השרת שולח HTML ריק + JS; הדפדפן בונה הכל
דוגמאות WordPress, PHP, אתרים ישנים React, Angular, Vue
getPageSource() מכיל את כל התוכן — שימושי לבדיקה מכיל HTML כמעט ריק — לא שימושי לתוכן ויזואלי
gov.il משתמש ב-Angular (CSR) — רוב התוכן נבנה ע"י JavaScript בדפדפן
דימוי לSSR vs CSR:
SSR = מסעדה שמגישה אוכל מוכן לגמרי — מה שמגיע לשולחן = מה שאוכלים.
CSR = ערכת IKEA — מקבלים קופסה עם חלקים (HTML + JS), ורק בבית מרכיבים לרהיט מוכן (DOM). לפני ההרכבה — הקופסה כמעט ריקה.
✅ מתי כן משתמשים ב-getPageSource()? – דוגמאות מעשיות

מקרה 1 – אימות encoding (חשוב לעברית)

String source = driver.getPageSource();
// בדיקה שה-charset מוגדר כ-UTF-8
Assert.assertTrue(source.contains("charset=\"UTF-8\""));

מקרה 2 – בדיקת JSON מוטמע

String source = driver.getPageSource();
// בדיקה שה-config שהשרת שלח מכיל את הגרסה הנכונה
Assert.assertTrue(source.contains("\"version\": \"2.1\""));

מקרה 3 – בדיקת SEO meta tags

String source = driver.getPageSource();
// בדיקה שדף הבית מכיל description לגוגל
Assert.assertTrue(source.contains("meta name=\"description\""));
Assert.assertTrue(source.contains("ממשלת ישראל"));
כלל אצבע: השתמש ב-getPageSource() כאשר המידע לא גלוי בממשק, נמצא ב-<head>, או מוטמע בתגיות <script>. לכל שאר הבדיקות — השתמש ב-driver.findElement().
❌ מתי לא כדאי להשתמש ב-getPageSource()?
מטרההדרך הנכונהלמה לא getPageSource?
לחיצה על כפתור driver.findElement(By.id("btn")).click() מחרוזת טקסט — אי אפשר ללחוץ עליה
בדיקה שטקסט מסוים מוצג element.getText() חיפוש ב-String לא מאמת שהאלמנט גלוי
מציאת אלמנטים ויזואליים By.cssSelector() / By.xpath() getPageSource לא מאפשר סלקטורים — רק contains()
בעיה נפוצה של מתחילים: לנסות לבדוק תוכן ויזואלי עם getPageSource().contains() — זה עלול לעבוד גם כשהאלמנט מוסתר (hidden)! findElement() מדויק יותר כי הוא בודק את ה-DOM החי.
📊 סיכום: getPageSource() מול findElement()
getPageSource()findElement() / cy.get()
מה מחזיר מחרוזת טקסט של ה-HTML אובייקט אלמנט ב-DOM
גישה חיפוש טקסט (contains) סלקטורים — CSS, XPath, ID
מכסה head, script, comments, meta אלמנטים גלויים ב-body
מתאים ל meta tags, JSON מוטמע, CSRF tokens לחיצות, קריאת טקסט, בדיקות ויזואליות
התשובה הנכונה היא: To find elements within JS code embedded in HTML.

getPageSource() מחזירה את כל קוד ה-HTML של הדף, כולל תגיות <script> שמכילות נתוני JSON מוטמעים — תוכן שלא גלוי כאלמנט ב-DOM ולא ניתן למצוא עם findElement().

שאר האפשרויות שגויות:
  • היא אינה מיותרת לחלוטין — יש לה שימושים ספציפיים
  • היא אינה הדרך החכמה למצוא אלמנטים ב-DOM — לזה משמש findElement()
  • האפשרות על "התאמת קוד שרת למנוע הדפדפן" אינה מדויקת — זה לא השימוש הנכון של הפקודה

ניתוח קוד Java – מה יודפס?

לוגיקה ולולאות
int n1 = 55, n2 = 66, hint = 1;

for(int i = 1; i <= n1; ++i)
{
  if(n1 % i==0 && n2 % i==0)
    hint = i;
}
System.out.println("hint is: " + hint);

כדי לענות, צריך להבין שני מושגים: אופרטור ה-Modulo וכיצד לעקוב אחרי לולאה.

אופרטור % (Modulo) – שארית חלוקה
a % b מחזיר את השארית של חלוקת a ב-b.
כאשר התוצאה היא 0 — b מחלק את a בדיוק ללא שארית.

דוגמאות:
10 % 5 = 0  → 5 מחלק את 10 בדיוק
10 % 3 = 1  → 3 לא מחלק את 10 בדיוק
55 % 11 = 0 → 11 מחלק את 55 בדיוק

מה הלולאה עושה בפועל?

הלולאה עוברת על כל מספר i מ-1 עד 55. בכל איטרציה בודקת: "האם i מחלק גם את n1 וגם את n2?" אם כן — שומרת את i ב-hint. בסוף הלולאה, hint מכיל את הערך האחרון שעמד בתנאי.

הסבר ויזואלי של ה-if בתוך הלולאה:

1
הלולאה בוחרת ערך נוכחי של i
2
בודקים אם 55 % i == 0
3
בודקים אם 66 % i == 0
4
רק אם שני התנאים נכונים נכנסים ל-if
5
hint מקבל את הערך של i
i 55 % i == 0? 66 % i == 0? נכנסים ל-if? מה קורה ל-hint?
1 כןכןכן hint = 1
5 כןלאלא נשאר 1
6 לאכןלא נשאר 1
11 כןכןכן hint = 11
55 כןלאלא נשאר 11
כלל פשוט לזכור: הסימן && אומר "וגם". מספיק שאחד משני הצדדים לא נכון כדי שלא ניכנס ל-if. נכנסים ל-if רק כאשר i מחלק גם את 55 וגם את 66 ללא שארית.
רמז מושגי: GCD – Greatest Common Divisor (מחלק משותף גדול ביותר)
האלגוריתם בקוד מחפש את המחלק המשותף הגדול ביותר של שני מספרים. המחלקים המשותפים של 55 ו-66 הם 1 ו-11. הלולאה עוברת בסדר עולה, ולכן hint מתעדכן לערך הגדול האחרון.

למה התוצאה הסופית היא 11?

המחלקים המשותפים של 55 ו-66 הם 1 ו-11. הלולאה עוברת בסדר עולה, ולכן hint קודם מקבל 1, ובהמשך מתעדכן ל-11. אחרי 11 אין מחלק משותף גדול יותר.

הפלט הסופי: hint is: 11

Rotate בבדיקות תאימות – מה זה ואיך בודקים?

Compatibility Testing Device Orientation

Rotate בבדיקות תאימות מתייחס לסיבוב מכשיר — מעבר בין Portrait (אנכי) ל-Landscape (אופקי).

מצבתיאורשימוש נפוץ
Portraitמוחזק אנכית (גובה > רוחב)גלילה, קריאה, אפליקציות רגילות
Landscapeמוחזק אופקית (רוחב > גובה)וידאו, משחקים, מפות

מה בודקים?

  • שהממשק מסתגל לרזולוציה החדשה
  • שלא מתרחשת קריסה בעת הסיבוב
  • שהמצב נשמר — נתוני משתמש, גלילה, טפסים
  • שתמונות וטקסטים אינם חותכים את המסך
כלים לאוטומציה:
כליפלטפורמהפקודה
AppiumAndroid / iOSdriver.rotate(ScreenOrientation.LANDSCAPE)
CypressWebcy.viewport(height, width)
SeleniumWeb / Mobiledriver.manage().window().setSize()

שלבים אופייניים:

  1. פתח ב-Portrait — ודא שהממשק תקין
  2. בצע פעולה (מלא טופס, גלול)
  3. סובב ל-Landscape
  4. ודא הסתגלות — אין חיתוך, אין קריסה
  5. ודא שמצב האפליקציה נשמר
  6. חזור ל-Portrait — בדוק שוב
📱 איך בודקים מעבר Orientation אוטומטית — עם דוגמאות קוד

בדיקת מעבר Orientation אוטומטית מחייבת שלושה דברים: (1) פקודה שמשנה את כיוון המכשיר, (2) המתנה שהאפליקציה תגיב לשינוי, (3) assertions שמוודאות שהכל תקין לאחר הסיבוב.

דוגמה 1 – Appium (אפליקציית Android / iOS)

Appium הוא הכלי הנפוץ ביותר לבדיקות Mobile אוטומטיות. הוא מאפשר שליטה על מכשיר פיזי או אמולטור ממש כמו משתמש אמיתי. 

// Java + Appium — Portrait → Landscape → Portrait

// Step 1: start in Portrait
driver.rotate(ScreenOrientation.PORTRAIT);
Thread.sleep(1000); // wait for animation to finish

// Step 2: verify UI is correct in Portrait
WebElement searchBtn = driver.findElement(By.id("search_button"));
Assert.assertTrue("Search button not visible in Portrait", searchBtn.isDisplayed());

// Step 3: rotate to Landscape
driver.rotate(ScreenOrientation.LANDSCAPE);
Thread.sleep(1000); // wait for the app to adapt

// Step 4: verify UI is still correct after rotation
Assert.assertTrue("Search button disappeared after rotation", searchBtn.isDisplayed());
Assert.assertEquals(driver.getOrientation(), ScreenOrientation.LANDSCAPE);

// Step 5: rotate back to Portrait and verify again
driver.rotate(ScreenOrientation.PORTRAIT);
Thread.sleep(1000);
Assert.assertTrue("Search button not visible after returning to Portrait", searchBtn.isDisplayed());
מה זה ScreenOrientation?
ScreenOrientation הוא Enum (ערכה סגורה של אפשרויות) ב-Appium. יש לו שני ערכים:
  • ScreenOrientation.PORTRAIT — כיוון אנכי (גובה גדול מרוחב)
  • ScreenOrientation.LANDSCAPE — כיוון אופקי (רוחב גדול מגובה)
driver.rotate() שולח פקודה למכשיר/אמולטור לבצע את הסיבוב בפועל.

דוגמה 2 – Appium עם שמירת מצב (State Preservation)

בדיקה חשובה: שנתונים שהמשתמש הכניס לא נמחקים אחרי הסיבוב.

שלב 1 — מלא שדה טקסט ב-Portrait ובדוק שהערך נשמר.
שלב 2 — סובב ל-Landscape והמתן לסיום האנימציה.
שלב 3 — מצא את אותו שדה מחדש וודא שהנתונים לא נמחקו. 

// Step 1: fill text field in Portrait and verify value
WebElement nameField = driver.findElement(By.id("name_input"));
nameField.sendKeys("John Doe");
Assert.assertEquals(nameField.getText(), "John Doe");

// Step 2: rotate to Landscape
driver.rotate(ScreenOrientation.LANDSCAPE);
Thread.sleep(1500);

// Step 3: verify data was NOT lost after rotation
WebElement nameFieldAfter = driver.findElement(By.id("name_input"));
Assert.assertEquals(
  "Data should be preserved after rotation!",
  nameFieldAfter.getText(),
  "John Doe"
);

דוגמה 3 – Cypress (בדיקת Web Responsive)

בדפדפן אין "סיבוב" פיזי — אבל אפשר לדמות את השינוי על ידי החלפת ממדי ה-viewport. Cypress מאפשר זאת בקלות. 

// Cypress — simulate Portrait → Landscape transition

describe('Orientation Tests', () => {

  it('should display correctly in Portrait mode', () => {
    // Portrait: width 390px x height 844px (iPhone 14)
    cy.viewport(390, 844)
    cy.visit('/')
    cy.get('[data-testid="search-btn"]').should('be.visible')
    cy.get('nav').should('be.visible')
  })

  it('should display correctly in Landscape mode', () => {
    // Landscape: swap dimensions — width 844px x height 390px
    cy.viewport(844, 390)
    cy.visit('/')
    cy.get('[data-testid="search-btn"]').should('be.visible')
    // verify no horizontal overflow (elements not cut off)
    cy.get('body').should('not.have.css', 'overflow-x', 'scroll')
  })

  it('should preserve form data after orientation change', () => {
    cy.viewport(390, 844) // Portrait
    cy.visit('/')
    cy.get('input[name="search"]').type('gov.il')

    cy.viewport(844, 390) // rotate to Landscape

    // verify typed text was preserved
    cy.get('input[name="search"]').should('have.value', 'gov.il')
  })

})
מה זה Viewport?
Viewport הוא השטח הגלוי של הדפדפן — הגודל שבו הדף מוצג. cy.viewport(width, height) משנה את המידות בזמן ריצת הטסט. כדי לדמות סיבוב: מחליפים בין (390, 844) ל-(844, 390). ב-Cypress יש גם שמות מוכנים: cy.viewport('iphone-x', 'landscape'). 
// Cypress — שימוש בשמות מכשיר מוכנים
cy.viewport('iphone-x')              // Portrait ברירת מחדל: 375×812
cy.viewport('iphone-x', 'landscape')  // Landscape: 812×375
cy.viewport('ipad-2')                 // Portrait טאבלט: 768×1024
cy.viewport('ipad-2', 'landscape')   // Landscape טאבלט: 1024×768

דוגמה 4 – XCUITest / Appium ב-iOS (Swift)

// Swift + XCUITest — iOS בלבד

func testOrientationChange() {
    let app = XCUIApplication()
    app.launch()

    // ודא שב-Portrait הכפתור מוצג
    XCUIDevice.shared.orientation = .portrait
    XCTAssertTrue(app.buttons["search"].exists)

    // סובב ל-Landscape
    XCUIDevice.shared.orientation = .landscapeLeft
    XCTAssertTrue(app.buttons["search"].exists, "כפתור נעלם אחרי סיבוב")

    // חזור ל-Portrait
    XCUIDevice.shared.orientation = .portrait
    XCTAssertTrue(app.buttons["search"].exists)
}

מה לבדוק אחרי כל סיבוב — Assertions מומלצות:
  • אלמנטים קריטיים (כפתורים, טפסים, תמונות) — עדיין גלויים
  • אין overflow אופקי (גלילה לצדדים לא רצויה)
  • נתוני טופס שהוכנסו לפני הסיבוב — עדיין קיימים
  • כיוון המכשיר השתנה בפועל (getOrientation)
