Fixtures – הפרדת נתוני טסט מלוגיקת הטסט

כל נתוני הטסט (מחרוזות עברית, endpoint paths, response bodies) הועברו לקבצי JSON בתיקיית cypress/fixtures/. הטסטים קוראים אותם עם cy.fixture() במקום לכתוב ערכים hardcoded.

למה?

  • שינוי נתון (למשל שם טאב) דורש עדכון בקובץ JSON אחד בלבד — לא חיפוש בכל ה-specs
  • נתוני הטסט גלויים ומרוכזים, קל לקרוא ולהבין מה הטסט בודק
  • בסיס לdata-driven testing עתידי (הרצת אותו טסט על מספר ערכים)

דפוס השימוש — cy.fixture().then():

// לפני – hardcoded
searchPage.typeQuery('דרכון')

// אחרי – נתון מגיע מ-fixture
cy.fixture('search-queries').then((q) => {
  searchPage.typeQuery(q.passportQuery)
})

דפוס השימוש — .as() ו-this (ב-myGovMenuTabs):

// טעינה פעם אחת ב-beforeEach
beforeEach(() => {
  cy.fixture('my-gov-tabs').as('tabs')
})

// שימוש בטסט — חובה function() ולא arrow function כדי ש-this יעבוד
it('should navigate', function() {
  const { urlSegment } = this.tabs.find((t) => t.label === 'תשלומים')
  page.verifyUrlIncludes(urlSegment)
})

טסטים לרכיב החיפוש – OOP Structure

Page Object Model

נבחר דפוס Page Object Model (POM) כדי להפריד בין לוגיקת הסלקטורים לבין לוגיקת הטסטים. כך הקוד קריא, ניתן לתחזוקה, וכשה-DOM משתנה — משנים רק במקום אחד.

cypress/pages/SearchPage.js
class SearchPage {

  // Selectors — getters מחזירים cy.get() חדש בכל קריאה
  get searchBtn() {
    return cy.get('button[aria-label*="חיפוש"], [class*="search-btn"]').first()
  }

  get searchInput() {
    return cy.get('input[placeholder*="חיפוש"], input[type="search"]').first()
  }

  get searchSuggestions() {
    return cy.get('[role="listbox"], [class*="suggestions"]')
  }

  // Actions
  visit()       { cy.mockGovPages(); cy.visit('/'); return this }
  openSearch()  { this.searchBtn.click(); return this }
  typeQuery(q)  { this.searchInput.should('be.visible').type(q); return this }
  submit()      { this.searchInput.type('{enter}'); return this }
  search(q)     { return this.openSearch().typeQuery(q).submit() }

  // Assertions
  verifySearchBtnVisible()   { this.searchBtn.should('be.visible'); return this }
  verifyInputVisible()       { this.searchInput.should('be.visible'); return this }
  verifySuggestionsVisible() { this.searchSuggestions.should('be.visible'); return this }
}

module.exports = SearchPage

למה getters ולא משתנים רגילים?
Cypress פועל באופן אסינכרוני. אם נשמור cy.get() במשתנה בתחילת הטסט, הסלקטור ירוץ לפני שה-DOM מוכן. Getter מחזיר חיפוש חדש בכל פעם שמשתמשים בו — כך מובטח שהאלמנט ייחפש ברגע הנכון.
התאמה לחסימת Cloudflare: לפני cy.visit() מופעל cy.mockGovPages(), כדי שהבדיקות ירוצו מול עמוד mock יציב שמכיל את כפתור החיפוש, שדה הקלט והצעות ההשלמה האוטומטית.

Intercept בקשות ובדיקת Status Code

cy.intercept + cy.wait

כאשר הדף נטען, הוא מבצע קריאות API לטעינת נתוני פילטר: cities, categories, ו-accessibilitytype. הטסט מיירט את שלושתן ומוודא שכל אחת מחזירה 200 OK.

הטסט משתמש ב-GovHomePage — Page Object שעוטף את הביקור בדף ואת הפעלת הבקשות. כך לוגיקת ה-setup מרוכזת במקום אחד ולא חוזרת בכל טסט.

cypress/pages/GovHomePage.js
class GovHomePage {
  visit() {
    cy.mockGovPages()
    cy.visit('/he/', { failOnStatusCode: false })
    return this
  }

  triggerApiFetch(...endpoints) {
    cy.window().then((win) => {
      endpoints.forEach((ep) => win.fetch(ep))
    })
    return this
  }
}
cypress/e2e/interceptStatusCode.cy.js
const GovHomePage = require('../pages/GovHomePage')

const page = new GovHomePage()

cy.fixture('api-endpoints').then((data) => {
  const paths = data.endpoints.map((e) => e.path)
  page.visit().triggerApiFetch(...paths)

  data.endpoints.forEach((e) => {
    cy.wait(`@${e.alias}`)
      .its('response.statusCode')
      .should('eq', data.expectedStatus)
  })
})

הסבר השלבים:

  • cy.fixture('api-endpoints') — טוען את רשימת ה-endpoints והסטטוס הצפוי מה-JSON
  • page.visit().triggerApiFetch(...paths) — ביקור בדף והפעלת הבקשות דרך ה-POM
  • data.endpoints.forEach() — עובר על כל endpoint ומוודא שקיבל 200
  • הוספת endpoint חדש לבדיקה = שורה אחת ב-api-endpoints.json בלבד

Intercept ושינוי ערך ה-title בתגובה

cy.intercept + Response Modification

כאשר נכנסים לדף של משרד ראש הממשלה, הדפדפן שולח בקשה לשרת שמחזירה JSON עם "title": "משרד ראש הממשלה". המשימה היא ליירט את הבקשה לפני שהדפדפן מרנדר אותה, ולשנות את ה-title ל-"office משרד ראש הממשלה".

הטסט משתמש ב-GovHomePage לניהול ה-visit וה-fetch. לוגיקת ה-intercept עצמה נשארת בתוך הטסט — היא ספציפית לטסט הזה ולא שייכת ל-POM.

cypress/e2e/modifyResponse.cy.js
const GovHomePage = require('../pages/GovHomePage')

const page = new GovHomePage()

cy.fixture('prime-ministers-office').then((dept) => {
// 1. visit() רושם את mockGovPages intercepts (כולל catch-all על /he/**)
page.visit()

// 2. רושם את @primeMinistersOffice אחרי mockGovPages — כך הוא גובר עליו
cy.intercept('GET', dept.interceptPattern, (req) => {
  const responseBody = {
    title: dept.originalTitle,
    department: { title: dept.originalTitle },
  }

  // פונקציה רקורסיבית שמוצאת ומשנה title בכל מבנה JSON
  const modifyTitle = (node) => {
    if (Array.isArray(node)) {
      node.forEach(modifyTitle)
    } else if (node && typeof node === 'object') {
      if (node.title === dept.originalTitle) {
        node.title = dept.modifiedTitle
      }
      Object.values(node).forEach((v) => {
        if (typeof v === 'object') modifyTitle(v)
      })
    }
  }

  modifyTitle(responseBody)
  req.reply({ statusCode: 200, body: responseBody })
}).as('primeMinistersOffice')

// 3. מפעיל את הבקשה אחרי רישום ה-intercept
page.triggerApiFetch(dept.apiPath)

cy.wait('@primeMinistersOffice')
  .its('response.body.title')
  .should('eq', dept.modifiedTitle)
})

למה צריך פונקציה רקורסיבית?

התגובה מהשרת היא JSON מקונן (nested) — אובייקטים בתוך מערכים בתוך אובייקטים. הפונקציה modifyTitle עוברת על כל הענפים ומשנה את ה-title בכל מקום שהוא מופיע, ללא תלות במבנה המדויק.

סדר רישום intercepts — חשוב: ב-Cypress, ה-intercept האחרון שנרשם מנצח על בקשות תואמות. cy.mockGovPages() רושם catch-all על /he/** — לכן @primeMinistersOffice חייב להירשם אחריו (כלומר אחרי page.visit()) כדי לתפוס את הבקשה ראשון.

my.gov – ארגון test cases לכל טאבי התפריט

describe נסטד לפי טאב

הארגון מבוסס על describe מקונן (nested describe): describe חיצוני לכל העמוד, ובתוכו describe נפרד לכל טאב. כך הדוח של Cypress מציג תוצאות מסודרות לפי טאב.

הטסט משתמש ב-MyGovPage — Page Object שעוטף את הביקור בדף, ניווט בין טאבים, ואסרציות בסיסיות. סלקטורים ספציפיים לתוכן (פריטי תשלום, מסמכים וכו') נשארים בטסט עצמו — הם assertion-specific ולא שייכים ל-POM.

cypress/pages/MyGovPage.js
class MyGovPage {
  get nav()       { return cy.get('nav, [role="navigation"], [class*="menu"]') }
  get activeTab() { return cy.get('[aria-selected="true"], [class*="active"]') }

  visit()            { cy.mockGovPages(); cy.visit('/my-gov'); return this }
  clickTab(label)   { cy.contains('a, button', label).click(); return this }
  verifyNavVisible() { this.nav.should('be.visible'); return this }
  verifyUrlIncludes(segment) { cy.url().should('include', segment); return this }
}

עקרונות הארגון:

  • MyGovPage — מרכז את כל הניווט והסלקטורים של העמוד במקום אחד
  • beforeEach() חיצוני — page.visit() טוען מחדש את עמוד ה-mock לפני כל טסט
  • beforeEach() בכל describe של טאב — page.clickTab() מנווט לטאב
  • כל טאב בודק: ניווט (URL), תצוגה (אלמנטים), פעולות (לחיצה, עריכה)
  • הטאבים נבדקים בעברית: תשלומים, פניות, מסמכים, הגדרות ושירותים
הערת אימות: my.gov.il משתמש ב-eZimun (SSO ממשלתי). בגלל שאין למטלה סביבת staging או הרשאות התחברות, הבדיקות רצות מול mock מקומי בנתיב /my-gov. בסביבת בדיקות אמיתית היה נכון להשתמש ב-cypress.env.json וב-cy.session() עם משתמש בדיקות מאושר.
